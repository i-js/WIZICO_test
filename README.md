# Список дел / Collaborative Todo List

Совместный список задач для двух пользователей: NestJS, Next.js App Router, Socket.IO, PostgreSQL и Prisma. Реализованы приглашения по ссылке, роли, drag & drop, присутствие, конфликты текста и сохраняемая офлайн-очередь.

## Запуск всего стека

Нужен Docker с Compose:

```bash
docker compose up --build -d
```

Откройте <http://localhost:3100>. API: <http://localhost:3101/health>.

Compose создаёт отдельную базу, применяет миграции и добавляет два демонстрационных аккаунта. PostgreSQL доступен с компьютера на `localhost:5544`. Порты 3000 и 5433 не используются.

| Пользователь | Email             | Пароль        |
| ------------ | ----------------- | ------------- |
| Алиса        | alice@example.com | demo-password |
| Борис        | bob@example.com   | demo-password |

Для одновременного входа используйте обычное окно и инкогнито либо два разных браузера: cookie общая для вкладок одного браузерного профиля.

Создайте список, нажмите «Пригласить участника» и откройте полученную ссылку во второй сессии. Создатель конкретного списка становится его владельцем. Один пользователь может иметь разные роли в разных списках.

Остановка без удаления данных:

```bash
docker compose down
```

Секрет JWT и пароли в Compose предназначены для локальной демонстрации. Для своего окружения скопируйте `.env.example` в `.env` и измените значения. При удалённом запуске `NEXT_PUBLIC_API_URL` должен быть адресом API, доступным браузеру; после изменения нужна пересборка web. Для HTTPS включите `COOKIE_SECURE=true` и задайте точные `WEB_ORIGINS`.

## Разработка без контейнеров приложений

Нужен Node.js 24. PostgreSQL можно оставить в Docker:

```bash
cp .env.example .env
npm ci --no-audit
docker compose up -d db
npm run db:generate
npm run db:migrate
npm run db:seed
npm run dev
```

Если `.env` уже создан и настроен, сохраняйте его значения. Не запускайте локальные приложения одновременно с контейнерами api/web на тех же портах.

Для production-сборки локально:

```bash
npm run build
npm start
```

Изменения API пересобираются в dev-режиме. После изменения общего пакета `contracts` выполните `npm run build:contracts`.

## Проверки

С запущенной базой и настроенной `.env`:

```bash
npm run typecheck
npm test
npm run build
npm run format:check
```

С запущенными API и frontend:

```bash
npx playwright install chromium
npm run test:e2e
```

При использовании уже установленного Chromium можно передать путь в `PLAYWRIGHT_EXECUTABLE_PATH`.

Серверные тесты создают собственных пользователей с уникальными ID и очищают только связанные с ними данные. Для автоматизации вне локального проекта рекомендуется отдельная тестовая БД. Если `DATABASE_URL` не задан, серверная интеграционная группа пропускается.

Браузерные проверки создают списки с префиксом `E2E`; их можно удалить через интерфейс. Тесты проверяют совместную работу, ограничения удаления, присутствие, сохранение черновика удалённой задачи, разрешение конфликта, восстановление очереди после перезагрузки и сортировку с клавиатуры. При ошибке сохраняются скриншоты и trace в `test-results`.

## Ключевые решения

- **Один авторитетный сервер.** Клиент отправляет команды, сервер проверяет права и правила, сохраняет результат и рассылает снимок списка.
- **Конфликт текста:** `expectedTextVersion`. Устаревшее редактирование возвращает конфликт, оба текста доступны пользователю. Автоматического посимвольного слияния нет.
- **Порядок:** команда перемещения перед ID другой задачи; сервер последовательно применяет операции под блокировкой строки списка. Позиции остаются целочисленными и непрерывными.
- **Повторная доставка:** ID команды и запись `ProcessedCommand` в одной транзакции с изменением. Повтор не применяет действие второй раз.
- **Офлайн:** IndexedDB хранит подтверждённые снимки и очередь. Web Locks координирует отправку между вкладками, BroadcastChannel обновляет их состояние.
- **Подтверждение:** ack или серверное событие, содержащее ID команды и ID её автора. Повтор старой команды возвращает текущее состояние, включая факт удаления списка.
- **Восстановление:** снимок при подключении и сверка ревизий каждые пять секунд закрывают пропущенные рассылки. Неизменившийся открытый список повторно не загружается; параллельные сверки объединяются. Более старые ревизии игнорируются.
- **Авторизация:** JWT в HttpOnly cookie, два seed-пользователя, срок сессии восемь часов. Права читаются из БД, а не из клиентского payload.
- **Типы:** общие Zod-схемы для команд, `z.infer` для TypeScript, отдельные типы ответа, ошибок, БД и локального состояния.

## Границы реализации

- Офлайн означает потерю WebSocket-соединения в уже открытом приложении. Снимки, команды и черновик сохраняются при перезагрузке; для загрузки самого сайта после перезагрузки нужен HTTP-доступ. Service worker для полностью автономного запуска не добавлен.
- Приглашение создаётся и принимается онлайн. Ссылка одноразовая, действует 24 часа. Вместо почтовой доставки выбран разрешённый заданием вариант со ссылкой.
- Текст сохраняется целиком по кнопке. Presence показывает редактируемую задачу, а не позицию каждого символа.
- При конфликте зависимая очередь этого списка приостанавливается; остальные списки продолжают отправку. Согласование текста объединяет последующие текстовые правки и сохраняет операции выполнения, перемещения и удаления. Новые правки во время ручного согласования требуют явного выбора; изменение очереди из другой вкладки проверяется атомарно. Отбрасывание действия удаляет зависимые операции; интерфейс предупреждает об этом и предлагает копирование текста.
- Нужен современный браузер с IndexedDB, Web Locks и BroadcastChannel; для этих API используйте localhost или HTTPS.
- Один экземпляр API. Presence живёт в памяти; после перезапуска восстанавливается подключениями. Для нескольких экземпляров потребуются общий Socket.IO adapter и общее хранилище presence.
- Полные снимки, вычисление позиций за O(n), отсутствие постраничной загрузки и неограниченное хранение квитанций выбраны для масштаба тестового задания. При сортировке БД обновляет только изменившиеся позиции пакетами до 1000 строк. Большие списки потребуют дельт, более экономичной сортировки и политики хранения.
- Вход ограничен 30 попытками в минуту на IP и 10 попытками за пять минут на email; превышение возвращает HTTP 429 и `Retry-After`. Счётчики живут в одном процессе API и сбрасываются при перезапуске. За reverse proxy необходимо настроить доверие к конкретному прокси, иначе IP-лимит будет общим для его клиентов; заголовок `X-Forwarded-For` по умолчанию не доверенный. Для нескольких API нужен общий rate limiter. Недоступность БД возвращается как временная ошибка и не аннулирует сессию.
- JWT не отзывается глобально через blacklist. Выход очищает cookie и закрывает клиентские сессии вкладок текущего профиля. Регистрация, refresh token и восстановление пароля не входят в реализацию.
- Docker-образы сохраняют исходники и dev-зависимости ради простоты запуска. Для промышленного деплоя нужны отдельные минимальные runtime-образы, секреты окружения и дополнительные эксплуатационные меры.
